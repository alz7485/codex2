# E3D 4.0 実機確認の設計

作成日: 2026-10-16。状態: **確認手順の設計。実行結果は未登録。**

[出力前確認・出力設計](export-workflow.md)の段階 C に向けて、対応可能と判断するための証拠を定める。提示写真の資料を E3D 4.0 の実行結果に読み替えない。入力例は架空の自作データを使い、資料のマクロ一式・原図・実プロジェクト情報を転載しない。

## 1. 証拠の単位

「SCYL が動いた」という一括判定にせず、作成、所有先、属性、単位、式、参照、表示を分ける。対応表の各項目から、確認したケースと条件を参照できるようにする。

| 項目 | 記録する内容 |
| --- | --- |
| 証拠 ID | 例 `EV01-001`。更新時も過去の記録を消さない |
| 対象環境 | E3D の版・ビルド、モジュール名、OS、関連する設定 |
| ケース | 下記 EV01–EV12 と、R 番号があればその番号 |
| 入力条件 | 最小の自作定義・値・参照関係、開始時の作業単位、現在要素・所有先 |
| 実行操作 | 自作の最小入力と操作順。対応表へ採用する正確な綴り・引用・単位表記 |
| 期待 | 資料から導く仮説、またはツールで満たすべき振る舞い |
| 観測 | 属性の問い合わせ結果、位置・方向・寸法、エラー、再描画操作 |
| 判定 | `passed / failed / inconclusive`。未実施は `not_run` |
| 適用範囲 | 確かめた型・属性・式・条件。一般化できない範囲 |
| 根拠 | 確認日と確認者、機密を除いた出力テキスト。画像は公開許可がある自作画面のみ |

ログにエラーがなかっただけでは成功にしない。入力後の属性・所有・参照と、必要な数値結果を照合する。画像だけで数値一致を判断しない。

## 2. 最初の実行出力に必要なケース

| ID | 最小の確認 | 期待と確認点 | 対応表への影響 |
| --- | --- | --- | --- |
| EV01 | 架空の CATA → SECT → CATE と Section 直接所属を作る | OWNER、許される型、各親での作成を問い合わせる。PTSET/GMSET は部品の子にしない | 所有可能な親子と作成順 |
| EV02 | PTAXI/PTCAR/PTMIX 各1点を明示値で作る | 型・NUMB・距離/座標・向き。省略した場合の +Y/0 も別条件で確認 | 点の作成・省略属性 |
| EV03 | SCYL を軸+Z、PDIS=12mm、PHEI=30mmと−30mmで比較。NSCYも別条件で同様に確認 | 基点12mm、反対側42mmと−18mmという仮説を数値で検証。SCYLの結果をNSCYへ流用せず、各型で証拠を残す。他型へ負高さを一般化しない | 各型で確認した符号付き高さ |
| EV04 | 自作の PARAM 数値・WORD と、値を参照する寸法・接続を作る | 型、番号、値、式保存、評価結果を問い合わせる。式が値に固定されていないこと | PARAM 配列・数値/WORD・基本式 |
| EV05 | 作業単位を mm と inch に変え、明示単位と裸の +3 を比較 | 同じ物理寸法と、幾何式の DB 単位評価を確認。実値入力時の単位規則は別に確認 | 数値と式の単位表記 |
| EV06 | PTSET/GMSET を2部品で共有し、明示参照を設定する | 双方が同じ定義を参照し、異なる PARAM で寸法が変わる。実機名・参照属性の綴り | 参照の設定順と名前変換 |
| EV07 | 自作名・日本語説明・空文字・引用文字・改行を個別に入力する | 許される表記、保存値、文字コード、文字列と実行行の境界を確認 | 文字列の出力可否とエスケープ |

この7ケースを全部の型へ一括適用しない。初回は確認した単純 SCOM、点、円筒、基本属性だけを対応表へ登録する。未確認の複合方向・関数が含まれる定義は、その機能の証拠が揃うまで実行出力の対象外とする。

## 3. 拡張と矛盾の解消に使うケース

| ID | 確認対象 | 条件と記録 |
| --- | --- | --- |
| EV08 | PAXI/PTCDIR、関数、DD 属性 | 基本軸、負の第2軸、各平面の角度、多軸指定を別々に確認する。回転順、角度単位、式の保存も記録。R06に対応 |
| EV09 | TUBE / CL / OBST / LEVEL / 再描画 | フラグを1条件ずつ変え、両方ON、LEVEL外、OBST1/2を比較。コマンド直後・UPDATE後・Draw List再追加後を記録。PPOINTS/PLINESの開始値も初期状態を揃えて確認。R01–R05/R11に対応 |
| EV10 | PTSSET、NAREF、構造部品の参照 | PLINE名・メンバー順、未指定のNA/NAXI/ZAXI/原点+Y、並べ替えを確認。SPRF/SJOI/SFITはクラス別に所有先と参照属性を確認 |
| EV11 | 負形状、保温、暗黙 TUBE | 子の負形状・NGMSETを分けて所有と適用を確認。保温なし0寸法と不正寸法、TUBE/noGMSET の特例も別条件で確認。プレビューのブーリアン完成を前提にしない |
| EV12 | SPEC、説明/材質、GPART、選択表 | 最小1行から選択先・CATREF・テキスト参照を問い合わせる。DETAI/DETREFの有効範囲と階層を確認。写真で不足した構文を推測入力しない。R09/R10を含む |

PARAM 一覧の末尾削除・添字変更、既存部品の変更、COPY/INCLUDE/OLD、20個制限、設計配列上限は、初回の新規作成とは別の追加ケースにする。最初の出力が成功しても更新処理を対応済みにしない。

## 4. 対応表の採用ルール

- 対応表は製品・版・モジュール・機能ごとに証拠 ID を持つ。資料上の長表記と略記の関係も、実際に使用したものだけ登録する。
- `passed` で、入力後の必要な状態を照合した機能だけを実行出力へ有効化する。`failed / inconclusive / not_run` は有効化しない。
- 失敗してもプロジェクトの原文を消さない。対応表の条件を狭めるか、ツールの変換処理を直して再確認する。
- E3D の版やモジュールが変わった場合は以前の結果を自動で適用しない。影響するケースを再確認する。
- 表示の R01–R05 が未解決でも、それだけで無関係な部品属性の確認を無効にしない。表示コマンドを出力する際にその機能を判定する。
- 実行出力と自動実行を別機能にする。初回のツールはファイル生成まで。確認のための実機操作も、作業先と保存の扱いを明示して行う。

## 5. 記録の配置

実測結果が得られた段階で `docs/verification/e3d-4.0/` にケースごとの Markdown と必要な自作入力を追加する。現段階ではこのディレクトリや成功済みサンプルを作らない。公開できないログは GitHub に追加せず、機密を除いた事実と確認範囲だけを記録する。

実測の根拠が得られたら [未確認事項](../knowledge/open-questions.md) の該当項目へ証拠 ID を追記する。「資料確認」「ツールでの実装・テスト」「E3D 実機確認」の状態は引き続き別々に記載する。
